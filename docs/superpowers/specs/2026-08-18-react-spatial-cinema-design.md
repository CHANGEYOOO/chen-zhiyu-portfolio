# React 全程空间放映重构设计

日期：2026-08-18  
状态：待用户审阅  
目标平台：桌面端优先  

## 1. 目标

把陈智宇的个人网站从传统纵向作品集重构为一次连续的“空间放映”。浏览器窗口不是装作品的页面，而是承载影像、空间与章节转换的放映场。访问者沿一条明确的观看路径，从代表作进入，经过东方文化影像、商业品牌与直播空间，最后进入完整作品档案和个人联系信息。

这次重构迁移至 React，但不改变作品内容、媒体存储、公开内容 API、GitHub Pages 域名或 Cloudflare 媒体服务。React 用于组织章节状态、媒体生命周期和交互；GSAP 用于滚动编排；React Bits `RippleDistortion` 的 OGL 位移算法用于全场景水波后处理。

## 2. 体验原则

1. **作品优先。** 特效服务于镜头和空间，不覆盖作品判断所需的清晰度。
2. **连续放映。** 主路径是一条不断章的观看路线，而不是卡片列表或多个网页跳转。
3. **电影化转场。** 项目之间通过遮幅、景别推进、溶解、空间位移和光影切换连接，不使用模板式卡片飞入。
4. **克制界面。** 导航和状态信息使用轻量的 Vision Pro 式半透明玻璃；作品本身不加玻璃框。
5. **一个视觉重心。** 每个时刻只让一个主要画面成为焦点，避免多个视频和特效竞争。
6. **真实加载。** 开场进度反映首章必要素材的实际加载状态，不播放虚假百分比。

## 3. 整体观看结构

### 3.1 开场：进入放映

- 页面进入后显示极简加载场：近黑背景、细线进度与当前加载状态。
- 只预载首章开始所需的海报、首段视频元数据和首个可播放片段；后续章节按距离预取。
- 达到可播放阈值后，加载界面退场，画面从黑场中显影。
- 加载失败时保留海报和“进入静态版本”入口，不让访问者卡死在开场。

### 3.2 第一章：Cinematic Worlds

主项目：

- 2024《永劫无间》NBPL，作为首屏与全站代表作；
- 2023《永劫无间》Last One Standing；
- 《原神》5.0《燃动纳塔》。

视觉节奏从近景、材质和局部信息开始，随着滚动逐渐显露完整画面。项目间使用画面接管、暗场和速度变化完成转场，不返回作品列表。

### 3.3 第二章：Eastern Narratives

主项目：

- 山东卫视 2024 春晚《兰亭》；
- 山东卫视《像·羽》。

章节强调留白、雾感、书写性运动和横向空间展开。水波更接近宣纸、墨层或空气折射，不表现成游戏式能量特效。

### 3.4 第三章：Brand Films

首轮放映由三个品牌项目构成：

- Mercedes-Benz 品牌系列；
- LEGO CNY 系列；
- BEATBOT S1 PRO。

本章节奏更清楚、切换更精准，使用材质、产品形体和色块完成镜头匹配。品牌和项目名称只在必要时短暂出现，不长期压在画面上。

### 3.5 第四章：Livestream Set Worlds

- 以横向沉浸式照片墙展示直播间设计；
- 图片保持原始长宽比，不裁成统一卡片；
- 不在观看层标注项目名称、品牌或类别；
- 项目之间不出现列表标题，依靠空间、颜色和布景关系自然换场；
- 横向运镜与纵向页面进度绑定，形成摄影机掠过布景的感觉；
- 鼠标经过图片时只发生轻微景深、尺度和空间响应，不弹出传统说明卡。

直播数据仍以现有公开 API 为优先来源，本地 `livestream-projects.json` 作为静态内容源。图片顺序保持当前数据定义。

### 3.6 Archive：完整作品画廊

- 展示全部 TVC 项目，保留现有作品顺序、品牌、标题、类别、海报和视频地址；
- 采用编辑式非对称画廊，不使用固定三列等宽网格；
- 不同尺寸来自明确的视觉节奏规则，不随机打乱；
- 鼠标经过作品时，海报轻微放大并产生局部空间/折射响应；
- 点击后打开单一全屏播放器；默认播放原片声音；
- 同一时间只允许一个作品视频播放，关闭播放器即暂停并卸载媒体。

### 3.7 About 与 Contact

- 作为放映结束后的片尾，而不是独立简历页；
- 保留已确认的职业定位、简介、履历、教育、合作品牌和联系方式；
- 联系入口清晰可操作，电话与微信复制逻辑继续保留；
- 视觉上回到安静、清楚、可阅读的平面层。

## 4. 导航与输入

- 主体验依赖自然纵向滚动，滚动驱动章节进度；
- 角落保留章节导航入口，可直接跳转 Chapter 1–4、Archive、About、Contact；
- 导航使用钛灰半透明玻璃、背景模糊与大圆角，保持小面积；
- 鼠标保持系统指针，不加入装饰性光圈或对焦环；
- 鼠标移动只驱动全场景水波和局部作品响应；
- 键盘可访问导航、作品入口、播放器关闭与媒体控制。

## 5. 视觉系统

### 5.1 色彩

- 主背景：冷调近黑；
- 界面与文字：钛灰、雾白；
- 唯一界面强调色：克制的钴蓝；
- 作品影像保持原始颜色，不统一套色；
- 暖色只来自作品画面本身，不作为全站底色。

### 5.2 玻璃界面

- 玻璃只用于章节导航、播放控制和少量状态提示；
- 使用半透明、背景模糊、细描边和柔和圆角；
- 不使用大面积玻璃卡片，不把作品包装成 Vision Pro 应用面板。

### 5.3 排版

- 英文承担章节编号、短标题与导航；
- 中文承担身份、作品名称与必要说明；
- 标题保持横向展开和足够留白，避免窄列多行堆叠；
- 不在沉浸段落持续显示大段描述。

## 6. 动效系统

### 6.1 GSAP 职责

- 章节进入、退出与固定；
- 纵向滚动映射横向照片墙；
- 景别推进、遮幅、溶解与文字时序；
- Archive 作品的进入和悬停响应；
- 所有 ScrollTrigger 在 React 生命周期中创建和清理。

### 6.2 RippleDistortion 职责

React Bits 原组件仅处理一张图片，不能直接扭曲 DOM 和视频。因此重构使用其 OGL 位移场、波纹生成和复合思路，建立全站唯一的 WebGL 后处理层：

- 全站只创建一个 WebGL/OGL 上下文；
- 当前章节的主图或视频帧作为场景纹理；
- 指针移动在场景纹理上生成水波位移；
- DOM 导航与重要文字位于 WebGL 之上，保持清晰；
- 章节更换时替换纹理，不创建新的 WebGL 实例；
- 视频纹理仅在画面可见且播放时更新；
- `prefers-reduced-motion` 下停用连续扰动，保留静态画面和必要转场。

首轮建议参数：

| 参数 | 初始值 | 目的 |
| --- | ---: | --- |
| brushSize | 160 | 形成可感知但不局促的波纹范围 |
| strength | 0.045 | 避免画面像橡胶变形 |
| swirl | 0.35 | 增加轻微流动，不形成旋涡主体 |
| rings | 2.6 | 保持电影化的单次扩散感 |
| spread | 3.5 | 控制空间扩散速度 |
| fade | 1.0 秒 | 指针离开后快速回归清晰 |
| tint | `#5877C8` | 与唯一钴蓝强调色一致 |
| tintAmount | 0.06 | 只在高光中可感知 |
| dispersion | 0.02 | 极轻的色散，不制造故障艺术感 |
| trigger | hover | 不依赖点击触发 |

这些参数是桌面端验证起点，最终以真实作品画面和 GPU 表现调整。

## 7. React 架构

采用 Vite + React 的单页静态构建，不引入路由器。页面仍发布到域名根路径，避免 GitHub Pages 刷新和路径回退问题。

建议模块边界：

```text
src/
├── app/                 页面组合与全局状态
├── chapters/            四个放映章节
├── archive/             完整作品画廊与播放器
├── about/               片尾信息与联系
├── motion/              GSAP 章节时间线
├── ripple/              单一 OGL 水波后处理层
├── media/               预载、视频生命周期与媒体状态
├── data/                作品 API、本地数据和规范化函数
└── styles/              色彩、排版、布局和动效变量
```

约束：

- 不引入 React Router；
- 不引入全局状态库，使用 React 状态与少量 Context；
- 不在 React 组件中硬编码作品；公开 API 是优先来源，构建内的静态作品快照是 API 不可用时的明确降级来源；
- 不把每个动效包装成抽象系统，只提取实际复用的章节与媒体能力；
- 现有 `/admin`、Cloudflare Workers、Supabase 文件和后台 API 不参与本轮重写。

## 8. 数据与媒体流

1. 页面加载公开作品 API；请求成功且数据有效时使用 API 内容，请求失败或返回无效数据时使用构建内的静态作品快照。静态快照由当前 30 个 TVC 和 8 个直播项目一次性迁移生成，不在运行时与 API 合并。
2. Loading Director 只选择首章必要资源加入真实进度。
3. 章节接近视口时预取下一章海报或视频元数据。
4. 当前章节激活时，媒体控制器把主媒体交给唯一 WebGL 场景层。
5. 离开章节后暂停视频并释放不再需要的帧更新。
6. 点击 Archive 作品后，单一原生播放器使用原视频地址播放并恢复原片声音。

`media.kjoe.top` 的图片和视频继续由 Cloudflare 提供，视频 Range 响应必须保留。WebGL 使用远程图片/视频纹理前，需要验证媒体域返回允许当前域名读取的 CORS 响应头。

## 9. 性能边界

- 桌面端目标为主流设备上接近 60fps；
- 全站仅一个 WebGL canvas、一个作品播放器和一个活动章节视频；
- 水波位移贴图使用低于显示分辨率的缓冲区；
- 不可见章节停止视频纹理更新和高频动画；
- 图片使用响应式尺寸、延迟解码和按章预取；
- 不把 55 张直播图片同时作为高分辨率 GPU 纹理；
- 页面隐藏时暂停 RAF 与非必要媒体；
- WebGL 不可用时展示清晰的普通影像，内容和导航仍然可用。

## 10. 声音规则

- 开场和主路径全程静音，不自动播放声音；
- 只有用户点击进入完整作品播放器后才播放原片声音；
- 浏览器自动播放失败不阻断画面体验；
- 播放器关闭、切换作品或按 Esc 时立即停止声音。

## 11. 部署与版本

- 继续使用 GitHub Pages 发布 `kjoe.top`；
- 继续使用 Cloudflare/R2 提供媒体和 Range 请求；
- Vite 输出静态 `dist/`，发布流程只替换前台构建产物；
- `CNAME` 必须包含在最终发布目录；
- 现有 `/admin` 与 Worker 不随前台构建被覆盖；
- 正式发布时递增可见版本号，并对变更的脚本与样式使用新的构建指纹或 cache bust；
- 本轮首先只在本地验证桌面端，不发布线上、不修改生产配置。

## 12. 验收标准

### 观看体验

- 从加载到 Contact 是一条连续空间放映路线；
- 四个章节具有不同气质，但属于同一视觉世界；
- 章节跳转入口始终可发现且不会遮挡主要作品；
- 直播章节呈现无文字的横向沉浸照片墙；
- Archive 能访问全部作品和完整播放器。

### 水波效果

- 鼠标移动时整个主场景产生连续、可见、克制的流体位移；
- 导航和关键文字保持清晰；
- 水波可作用于主图及活动视频画面；
- 不出现装饰性鼠标、对焦环或明显跟手圆形贴图；
- 停止移动后画面自然恢复，不长期抖动。

### 技术

- React 构建可在本地静态服务器正常访问；
- 公开作品 API 失败时仍能显示现有作品；
- 同一时间只有一个活动视频和一个 WebGL 上下文；
- 视频播放器保留声音、Esc 关闭、失败提示与卸载；
- `prefers-reduced-motion` 和键盘操作可用；
- Chrome 与 Safari 桌面端完成视觉和性能验证。

## 13. 本轮不包含

- 移动端正式设计与触控水波方案；
- 修改后台管理界面；
- 修改 Cloudflare Worker、R2 数据或生产 CORS 配置；
- 上传、替换或删除线上媒体；
- 迁移域名或托管平台；
- 新增未经确认的个人信息和作品内容。
